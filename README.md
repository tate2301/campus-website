# Corelith Campus website

The marketing site for Corelith Campus (campus.corelith.co.zw), built from the signed-off design in `design/`.
Next.js (App Router, TypeScript, server components, static pages), Tailwind with the design tokens as CSS variables.
`CLAUDE.md` is the build brief; `NOTES.md` lists what could not be matched and why.

## Run it

```sh
npm install
npm run dev                 # http://localhost:3000
npm run build && npm start  # the production build, which the tests use
```

## Check it against the design

```sh
npm run build && npm start &
npm run test:visual                    # design/tests/visual.spec.ts, unchanged: every route at 1440 and 390 against the references
npm run parity -- --only home,pricing  # per route: vs the reference, the JPEG floor, and the design's own HTML; diffs in .parity/
```

`npm run parity` explains each result: `PASS` is within the acceptance test's limits, `FLOOR` is within 0.1 points of
what saving the page as the references were saved (JPEG, quality 86) costs on its own. See NOTES.md.

## How the code is laid out

| Path | What |
|---|---|
| `src/app/**/page.tsx` | One route per entry in `design/spec/routes.json`. Each renders the desktop layout and the phone layout; CSS shows one (phone up to 1023px). |
| `src/components/ds.tsx` | The design system's pieces (buttons, eyebrows, headings, cards, photos, tags), ported from `design/source/*.py` with the same names and values. |
| `src/components/sections.tsx`, `phone.tsx`, `templates.tsx` | Desktop sections, phone sections, and the shared department, school-type and role pages. |
| `src/components/cards.tsx`, `site-cards.tsx`, `who-sections.tsx`, `phones.tsx` | The product cards and phone mock-ups, with the school's fixed figures. |
| `src/components/art.tsx`, `src/art/registry.json` | Every drawn piece (icons, the Campus mark, department and school drawings, call-to-action scenes, the mark journey, brand logos), as the exact markup the design exported. |
| `src/content/copy.ts` | `design/content/copy.json`, the only source of copy. |
| `scripts/` | `parity.mjs`, `extract-art.mjs` (fills the drawing registry), `price-sheet-pdf.mjs`. |

### Drawings

The design's drawings were generated by code that is not in the handover, at each size they appear. They are kept as
the exact exported markup and rendered as React elements. To add or change one, render the page that uses it with
`ART_COLLECT=1 npx next dev -p 3100`, then run `node scripts/extract-art.mjs --only <slug>`: it finds each drawing's
place on the page and takes the piece at the same place in `design/html`. A key that resolves to two different pieces
means the markup around it differs from the design.

### The price sheet

`/pricing/price-sheet.pdf` is `public/pricing/price-sheet.pdf`, printed from `/print/price-sheet`:

```sh
npm run build && npm start &
npm run pdf
```

### Forms

`/demo` and `/contact` post to `src/app/api/demo` and `src/app/api/contact`, which check the request
(`src/lib/lead-route.ts`) and send it to the Corelith CRM's lead webhook (`src/lib/leads.ts`), as corelith.co.zw's
forms do. Copy `.env.example` to `.env.local` and set `CORELITH_CRM_API_KEY`; until it is set, submissions are only
written to the server log. NOTES.md has what arrives in the CRM and how spam is turned away.
